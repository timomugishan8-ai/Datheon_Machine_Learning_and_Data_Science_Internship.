# Predictive Customer Churn Classifier

A notebook-based machine learning project for exploring customer churn in a telecommunications dataset and preparing classification models to identify customers who may leave.

## Overview

The project follows a practical analytics workflow: inspect the raw data, explore churn patterns, prepare features, and construct Random Forest and XGBoost pipelines. The analysis is exploratory. Relationships observed in the data should not be interpreted as evidence that a particular factor causes churn.

## Project Goals

- Understand the distribution of churn and the characteristics associated with it.
- Prepare numerical and categorical customer features for modeling.
- Address class imbalance during model training.
- Develop a repeatable basis for comparing tree-based classifiers.

## Dataset

The project uses the Telco Customer Churn dataset at `data/raw/Telco-Customer-Churn.csv`. It contains 7,043 customer records and 21 columns, including the `Churn` target. The original target labels are `Yes` and `No`; the preprocessing notebook encodes them as `1` and `0`, respectively. Approximately 26.5% of customers in the dataset churned.

`TotalCharges` is stored as text in the source file. Converting it to numeric reveals 11 blank values, associated with customers who have zero tenure. The EDA notebook fills these values with `MonthlyCharges * tenure` for its analyses; the preprocessing notebook instead includes median imputation in the numerical feature pipeline.

## Notebook Workflow

Run the notebooks in order, from the `notebooks/` directory or with the notebook server configured to use that directory as the working directory. The notebooks use relative paths such as `../data/raw/...`.

| Notebook | Purpose | Main output |
|---|---|---|
| [01_customer_churcn_eda.ipynb](notebooks/01_customer_churcn_eda.ipynb) | Inspects data quality and explores churn by contract, tenure, charges, services, payment method, and customer attributes. | Charts, statistical comparisons, and exploratory observations. |
| [02_data_preprocessing.ipynb](notebooks/02_data_preprocessing.ipynb) | Removes the customer identifier from the predictors, converts the target to numeric, splits the data, and defines imputation and one-hot encoding steps. | `data/processed/cleaned_telco_churn.csv`. |
| [03_model_development.ipynb](notebooks/03_model_development.ipynb) | Loads the processed data, creates a stratified train/test split, defines preprocessing, and constructs Random Forest and XGBoost pipelines with SMOTE. | Model pipeline definitions. |
| [04_model_evaluation.ipynb](notebooks/04_model_evaluation.ipynb) | Reserved for model evaluation. | Not implemented yet. |

The preprocessing notebook fits its example preprocessor on the training partition to demonstrate the transformation. The saved CSV contains the cleaned feature data and numeric target; the model-development notebook creates its own train/test split from that file.

## Exploratory Findings

The EDA notebook reports several patterns worth investigating further:

- Month-to-month customers have the highest churn, particularly during their first year.
- Churn is higher among fiber-optic customers and among internet customers without online security.
- Customers using electronic checks have higher observed churn than customers using other payment methods.
- Customers who churned had shorter tenure on average; among month-to-month customers, churners also had higher average monthly charges.
- Senior customers show higher churn rates than non-senior customers within each contract category in the grouped analysis.

These are descriptive or unadjusted statistical comparisons. Customer groups overlap, and the notebook does not establish that any single factor causes churn. The service-count analysis also uses a simple feature count, so it should be interpreted cautiously.

## Modeling Approach

The model-development notebook uses a stratified 80/20 train/test split. Numerical features are median-imputed; categorical features are imputed with their most frequent value and one-hot encoded. The resulting pipelines apply SMOTE to address the class imbalance, then use either a Random Forest classifier or an XGBoost classifier. Feature scaling is not included because both classifiers are tree-based.

In the current implementation, standard SMOTE is applied after one-hot encoding. For categorical data, assess whether a categorical-aware resampling strategy such as SMOTENC is more appropriate before using model results. The notebook imports evaluation and search utilities, but the current version does not fit the pipelines, tune parameters, or report test-set metrics.

## Setup

Use a Python environment with Jupyter and the libraries used by the notebooks. The `requirements.txt` file is currently empty, so install the dependencies directly:

```bash
python -m venv .venv
```

Activate the environment, then install the packages:

```bash
python -m pip install pandas numpy matplotlib seaborn scipy scikit-learn imbalanced-learn xgboost jupyter
```

On Windows PowerShell, activate the environment with:

```powershell
.venv\Scripts\Activate.ps1
```

On macOS or Linux, use:

```bash
source .venv/bin/activate
```

Start Jupyter from the project root and open the notebooks:

```bash
jupyter lab
```

Run notebooks 01 through 03 in sequence. Notebook 02 creates the processed CSV required by notebook 03. Notebook 04 is currently an empty placeholder.
